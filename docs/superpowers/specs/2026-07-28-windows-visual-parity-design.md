# Windows Vulkan Visual Parity Design

## Goal

Make the production Windows/Vulkan renderer visually comparable to the
retained legacy r3d renderer before doing further steady-state performance
optimization or macOS/Metal closeout work.

The target is not pixel identity. The target is the same readable gameplay
composition, material intent, occlusion, transparent layering, color grade,
focus treatment, and active effects at 1920x1080. Existing goldens, cue
bounds, SSIM thresholds, and entity authority stay unchanged.

## Evidence and priority

The current five-mode capture has correct content and stable same-source
output, but direct inspection against the approved legacy capture exposes two
high-impact classes of divergence:

1. The production scene pipeline always disables culling, enables blending,
   and writes depth. `alphaCutoff`, stencil state, and most material raster
   state never reach the native renderer. Transparent and additive geometry
   is submitted in the opaque pass without a transparent ordering contract.
   In Game and Combat Lab this collapses the center of the battle into
   incorrectly occluded and layered geometry.
2. The production scene renders directly to the swapchain and ignores the
   active environment/post contract. Reinhard white point, SSAO, LUT, CAS,
   and tilt-shift are therefore absent. The result is materially darker and
   sharper than legacy, even where scene geometry itself is correct.

The current GPU resource layer also stores game surface-shader descriptors
without applying them to production draws. The active game-authored
semantics include at least water, static glitter/highlight, dissolve, and
shatter. They must be ported as explicit offline renderer variants; arbitrary
runtime GLSL compilation is not introduced.

## Selected approach

Visual parity is delivered in three dependency-ordered slices.

### Slice A: surface and render-queue semantics

Project the complete active material raster contract through Swift and the
internal C boundary:

- alpha cutoff and albedo alpha;
- depth compare and transparent depth-write policy;
- cull mode;
- stencil compare, reference, mask, and operations;
- mix, additive, multiplied, and premultiplied-alpha blending;
- opaque, alpha-cutout, and transparent classification.

SDL GPU pipeline state is immutable, so native scene pipelines are selected
from validated variants. Opaque and alpha-cutout draws run first with depth
writes. Transparent draws run afterwards with depth testing and no depth
writes. Mix and premultiplied-alpha packets are stable-sorted back-to-front;
order-independent additive batches may remain grouped. Alpha-cutout affects
both the main pass and shadow casting. Cull and stencil state apply to the
main pass; compatible cull/alpha state also applies to shadow casters.

The queue must preserve persistent instance buffers. Where correct
transparent ordering requires per-instance order, Swift emits a sorted
transient view rather than mutating caller-owned persistent storage.

### Slice B: active environment and post chain

Render the 3D scene into a renderer-owned linear HDR color target with a
sampled depth target. Resolve it through explicit fullscreen passes before
the existing canvas/UI overlay:

1. optional SSAO composition;
2. Reinhard tonemap using the authored white point;
3. the game LUT;
4. CAS using the authored sharpness;
5. tilt-shift using the authored focus parameters;
6. scene-only SMAA when `FrameDescriptor.antiAliasing` requests medium or
   high quality.

Only the screen-shader semantics used by this game are supported. The Swift
resource layer classifies the known bundled shader descriptors and validates
their required parameters. Native pipelines use offline SPIR-V and Metal
artifacts generated by the existing shader build. An unknown screen shader
fails with a clear unsupported-operation error instead of being silently
ignored.

SMAA uses the retained area/search lookup assets and distinct medium/high
quality pipeline variants. It runs after scene tone/color/focus processing
and before the canvas. The canvas remains after post processing so HUD and
editor text are not blurred or tone-mapped.

### Slice C: active surface-shader variants and residual parity

Port the active game shader semantics as named offline variants, starting
with the variants visible in deterministic captures. Unknown surface shaders
fail closed instead of rendering as an unmodified material.

After each variant, compare all five modes to both the immediately preceding
GPU capture and the unchanged legacy authority. Residual differences are
classified as geometry/raster, lighting/environment, post, UI, or the
already documented cross-platform text/antialiasing issue.

## Interfaces and invariants

- Public renderer descriptors stay backend-neutral.
- Internal C structs may grow only with matching validation and Swift
  projection tests.
- No backend silently substitutes OpenGL or D3D12.
- No visual feature is accepted solely from a unit test; each slice includes
  a real Windows/Vulkan image probe and a five-mode capture.
- Entity signatures, clean shutdown, and 1920x1080 output remain mandatory.
- The known legacy Game signature mismatch (`13185` versus current `13196`)
  remains documented and is not bypassed by changing the authority.
- The historical Windows-to-Apple text and antialiasing SSIM issue is not
  claimed fixed by Windows platform-local work.
- Performance is measured after every slice. A greater-than-five-percent
  regression is diagnosed before proceeding, but visual parity is the
  current ordering priority.

## Acceptance criteria

The Windows visual phase is complete when:

- focused native and Swift tests prove every projected raster state and
  render-queue rule;
- real Vulkan probes visibly distinguish opaque depth writing, alpha-cutout,
  culling, stencil rejection, and transparent ordering;
- Game and Combat Lab no longer show the current center-stack
  occlusion/layering defect;
- active tonemap, LUT, CAS, tilt-shift, SSAO, and exercised surface variants
  are no longer silently ignored;
- `.smaaMedium` and `.smaaHigh` are projected to real scene-only SMAA passes,
  while `.off` bypasses them;
- all five modes capture twice with identical entity signatures, clean
  shutdown, and 1920x1080 output;
- same-source comparisons pass unchanged gates, and the comparison to legacy
  shows a materially closer result without changing goldens or thresholds;
- remaining differences are explicitly documented rather than declared
  solved.
